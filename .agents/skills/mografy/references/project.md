# Mografy project reference

Canonical sources are on [GitHub](https://github.com/mografy/mografy). Resolve local files from the current checkout, never from a path in another installation. For an animation project elsewhere, read that project's settings and assets; do not assume it is inside this repository.

Before product changes, read [AGENTS.md](https://github.com/mografy/mografy/blob/main/AGENTS.md), [architecture](https://github.com/mografy/mografy/blob/main/.agents/skills/mografy/references/dev-architecture.md), [status](https://github.com/mografy/mografy/blob/main/docs/STATUS.md), and [usage](https://github.com/mografy/mografy/blob/main/README.md). For packing, installing or releasing the npm package, read [npm-package.md](https://github.com/mografy/mografy/blob/main/.agents/skills/mografy/references/dev-npm-package.md); for install layouts, folders and environment variables, [configuration.md](https://github.com/mografy/mografy/blob/main/.agents/skills/mografy/references/configuration.md); to show that a Skill revision is better, [dev-skill-evals.md](https://github.com/mografy/mografy/blob/main/.agents/skills/mografy/references/dev-skill-evals.md).

- `packages/core/skill/` holds the English Skill entrypoint and references as Markdown; `packages/core/src/guide.ts` assembles them, publishing every file in `skill/references/` (link a new one from `SKILL.md` or another reference; `https://github.com/mografy/mografy/blob/main` is filled with the repository's URL). When `project-guide.md` or the Skill pointer changes, copy the outgoing text into `guide-legacy.ts` so unedited old AGENTS.md files still update. After changes, run `pnpm build` in the repository; it ends with `pnpm sync:skills`, which regenerates the Skill. `npx mografy dev` also regenerates it when its sources changed since the last sync.
- Use `npx mografy update --check` to check the executing source installation, or `npx mografy update` to fast-forward, install/build, sync guidance and restart its active player. Stop and resolve local changes or diverged history rather than overwriting them. Older installations need a one-time manual update documented in README.
- One `mografy` Skill lives in the source repository's outer `.agents/skills/` folder, with scene, storyboard, animation-principle, and project references. Codex reads it there; the root `.claude/skills/mografy` symlink points Claude to the same folder. Root `CLAUDE.md` also imports the shared Skill. Never create Skill folders inside animation subprojects.
- Animation code belongs only in scene modules. The Server must never import or evaluate scenes in Node. Do not introduce GSAP, SVG scene layers, or resvg.
- Application writes to projects use `queueProjectWrite` in `packages/server/src/project.ts` and `atomicWrite`. The player and exports share `@mografy/runtime`, including `post.ts`.
- Run `pnpm check` and `pnpm test:browser` after repository changes. For scene work, use `npx mografy check --motion [project]`, `npx mografy review [project]`, and inspect the PNGs.

Adapt storyboards to the actual scene and assets. Write plans and prompts in English. Codex invokes image generation; Claude invokes Artifacts when exposed, with a standalone local HTML/Canvas fallback in Claude Code. Read the corresponding local references for details.
